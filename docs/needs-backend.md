# SentinelMesh Features Requiring Future Backend Enhancements

The current frontend implementation is 100% functional against the live FastAPI / SQLite offline backend (`http://localhost:8000`). For advanced enterprise extensions, the following items are currently adapted or mock-flagged:

---

## 1. Interactive "What-If" Sandbox Re-Execution
- **Current Adapter Behavior**: In the Mesh Assistant, queries that ask "What if threshold changes to X" provide analytical answers derived from static AST analysis and the causal chain. If `USE_MOCKS=true`, an experimental preview response is presented clearly labelled as simulated.
- **Backend Enhancement Needed**: An endpoint `POST /api/sandbox/re-execute` that accepts temporary parameter overrides and executes targeted pytest runs in an ephemeral container without creating a full project run.

---

## 2. Server-Side Bug State Transitions & Assignments
- **Current Adapter Behavior**: Bug lifecycle states (`Open` -> `Fix proposed` -> `Verified` -> `PR opened` -> `Merged`, plus `Dismissed` and `Assignee`) are persisted in browser `localStorage` keyed by `sentinel_workflow_{run_id}_{bug_id}`.
- **Backend Enhancement Needed**: Endpoints `PATCH /api/runs/{run_id}/bugs/{bug_id}/status` and `PATCH /api/runs/{run_id}/bugs/{bug_id}/assignee` to persist collaborative triage decisions in the SQLite database across multi-user sessions.

---

## 3. Webhook Delivery (Slack & Email Alerts)
- **Current Adapter Behavior**: The Integrations and Settings views allow configuring webhook URLs and notification preferences, storing them locally. A test alert indicates that notification dispatch is stored locally.
- **Backend Enhancement Needed**: Background webhook dispatcher in `backend/main.py` that posts JSON payloads to configured endpoints upon run completion.

---

## 4. Automated Git Push / Direct GitHub PR Creation
- **Current Adapter Behavior**: Clicking "Open PR" downloads the verified `.patch` file and opens the GitHub PR action helper modal with ready-to-paste git commands and PR descriptions.
- **Backend Enhancement Needed**: Integration with GitHub OAuth / Personal Access Tokens to automate `git checkout -b fix-branch`, `git apply patch`, and `gh pr create` directly on remote git repositories.

---

## 5. What-If Health Score Delta API (Item C - Estimated)
- **Current Adapter / UI Behavior**: Displays the mathematical health score impact of verifying a bug (`Score = (Coverage × 0.30) + (Mutation × 0.25) + (FixRatio × 0.30) + (PassRate × 0.15)`), clearly labeled with an **[Estimated]** badge.
- **Backend Enhancement Needed**: `POST /api/runs/{run_id}/bugs/{bug_id}/simulate-impact` returning the exact simulated suite health score, coverage delta, and regression risk before committing the patch.

---

## 6. AST Call Graph Dependency Mapping / Caller Impact (Item C - Estimated)
- **Current Adapter / UI Behavior**: Check 4 of the Merge Readiness gate checks for unaffected external callers. In the current backend, AST complexity is computed but an inter-procedural call-graph caller count is not returned in `BugResponse`. Labeled with an **[Estimated]** badge.
- **Backend Enhancement Needed**: Add `callers_count: int` and `affected_callers: List[str]` to `BugResponse` derived from static call graph analysis.

---

## 7. Multi-Run Historical Trend Aggregation (Item C - Sample Data)
- **Current Adapter / UI Behavior**: Displays the health trend sparkline and delta in the verdict banner, labeled with a **[Sample data]** badge when historical run baselines have not yet accumulated in SQLite.
- **Backend Enhancement Needed**: An analytics aggregation endpoint `GET /api/projects/{project_id}/health-trends` returning time-series health score sparkline coordinates and regression metrics across sequential runs.

---

## 8. Cryptographic Verifier Attestation Signatures (Item C / B - Derived)
- **Current Adapter / UI Behavior**: Generates a deterministic hash signature derived from the actual verified diff contents.
- **Backend Enhancement Needed**: Add `verifier_signature: str` and `attestation_timestamp: datetime` to `BugResponse` generated by the Verifier Agent using an HMAC key or ECDSA key for cryptographically tamper-evident PR receipts.
